# 船型カタログ（生成船型を型式と大きさから決める）

## 何を

`src/render/hull.ts` は全船を 1 つの形で描いている。平面形は尖った船首で固定、乾舷は「幅 × 0.55」、
船橋高は「幅 × 0.75」、船橋位置は「船長 × 0.32 後方」。水平寸法（L, B）はデータから来ているが、
**垂直寸法と形はすべて発明**。

代表船型のカタログを持ち、`type` / `grossTonnage` / (L, B) から引く形にする。

## なぜ

船型がクラスタするのは流体力学ではなく**規制とインフラ**が原因。499 は日本の内航規制の閾値、
VLCC はターミナルの水深、パナマックスは閘門の寸法。だからクラスタは連続量ではなく**名前のついた
離散的なもの**で、式で近似するより代表値のカタログを最近傍で引くほうが正しい。

499 総トン型貨物船の実測レンジ:

| | 範囲 |
| --- | --- |
| 全長 | 68.7 〜 76 m |
| 型幅 | 12.0 〜 13.2 m |
| 型深さ | 6.8 〜 7.4 m |

型深さがクラス内で 6.8〜7.4 に収まる。**比を推定するより代表値を持つほうが精度が高く、出典も
付けやすい**（造船所の仕様書がそのまま一次情報になる）。

**素直な実装だと何が間違うか。**

1. **L/B 比を型の判別に使う。** 同じ 499 型の中で 68.7/13.2 = 5.2 から 76/12 = 6.3 まで開く。
   **寸法比は弱いキー**。強いのはクラスのラベルのほうで、内航ではそれが総トン数そのもの
   （199 / 499 / 749）。`grossTonnage` はスキーマにあるが `core/types.ts:93` の宣言以外どこでも
   使われていない
2. **垂直寸法を L や B に比例させる。** 乾舷は満載喫水線条約で船長と型式の関数として決まる
   非線形量。比例配分すると大型船だけ異様に背が高くなる。**乾舷 = 型深さ − 喫水**という引き算で
   出す。型深さはクラスから、喫水は `draughtMetres` から。この `draughtMetres` も現在未使用で、
   例では Seitoku Maru に 3.7 が入っている
3. **L と B だけで型を決める。** `examples/` の中に反例がある。Spinner 2 は L/B = 6.37 で在来型
   貨物船に見えるが、実際は箱船首の押船＋バージ。`type: "pushing-ahead"` だけがそれを言う

キーの優先順位は **`type` → `grossTonnage` → (L, B)**。

## どう

カタログは `src/actors/vessel/` に置く（`core/` に船の概念を入れない）。1 クラス 1 行で、代表の
主要目と出典を持つ。

**船体モデルを N 本作る必要はない。** 3 km 視野・1920 px 幅では Spinner 2 が幅 12.2 px、
Seitoku Maru が 6.0 px。この幅で肥痩係数の違いは見えない。見えるのは 3 つだけ。

1. **船首形状**（尖っているか箱か）
2. **上部構造の前後位置**
3. **乾舷の高さ**

なので今の 1 本のパラメトリック形状に、船首と上部構造位置のスイッチを 2 つ足すだけでよい。型が
増えてもカタログに 1 行足すだけで済む。

**船橋位置はカタログの定数よりアンテナ位置のほうが実測に近い。** 多くの商船で GPS アンテナは
船橋の上かその近くにある。船首から測ると Seitoku Maru が 39/49 = 0.80 L、Spinner 2 が
104/121 = 0.86 L。現在の定数 0.82 L はこの 2 隻ではたまたま合っているが、船橋中央の在来型貨物船
では外れ、アンテナは正しく言う。`referencePointOffsets` があるときはそちらを使う
（`plans/antenna-offset-6.md` の副産物なので、そちらを先に入れる）。

**副産物として、外れたら疑える。** どのクラスにも合わない (GT, L, B) の組は、データの読み違いの
サイン。報告書の諸元欄の長さは登録長 Lr であって全長ではない（`CLAUDE.md`）ので、取り違えると
L/B が不自然になり、カタログとの距離で捕まえられる。`core/plausibility.ts` が速力で同じことを
やっているので枠組みは既にある。

**出所の話。** 生成された船型は「この船の形」ではなく「型式の代表形」。このレポは点ごとに
`derivation` を持たせているのだから、船体にも同じ誠実さが要る。パネルに 1 行出す。

## 入れたもの（資料の要らない部分）

カタログの表そのものは**出典待ちで書けない**（下記「詰まっているところ」）。資料ゼロで入る3つを先に入れた。

- **船橋位置をアンテナの実測から取る。** `-length * 0.32` を捨て、`referencePointOffsets` が
  あれば `-(船首 − 船尾) / 2`。plan が「カタログの定数より正確」と書いていた項目そのもの。
  実測は Seitoku Maru −0.30 L、Spinner 2 −0.36 L で、定数 0.32 はこの2隻に**たまたま**挟まって
  いただけ。船橋中央の在来型なら外れる
- **押船＋バージに箱型船首。** `type: "pushing-ahead"` が既に言っていることで、カタログは要らない。
  3 km 視野で Spinner 2 は幅 12 px、肥痩係数は見えないが**箱かどうかは見える**
- **パネルに「何に基づくか」を出す。** `box bow, bridge measured` / `generic, bridge assumed`。
  画面上で見分けがつかない2つを、点ごとの `derivation` と同じ誠実さで区別する

## 詰まっているところ

**乾舷 = 型深さ − 喫水。喫水はシナリオにあるが、型深さが無い。** 参照事案の報告書は喫水 3.7 m を
書いているだけで、型深さは書いていない。plan 自身が「**記憶で埋めない**」と決めているので、
カタログの行はここで止まる。要るのは造船所の仕様書か、それに類する一次情報。

`FREEBOARD_FRACTION_OF_BEAM` と `BRIDGE_HEIGHT_FRACTION_OF_BEAM` は発明のまま残っている。

## どのファイル

- 新規 `src/actors/vessel/hull-catalogue.ts` — クラスの表と最近傍マッチ
- `src/render/hull.ts` — 発明の定数 3 つをカタログ引きに置き換え、船首と上部構造位置のスイッチ
- `src/core/plausibility.ts` — カタログから外れた主要目の警告（別 issue に切ってもよい）
- `src/ui/panels.ts` — 船型が代表形であることの表示
- `test/hull.spec.ts` — 上の 3 つの罠それぞれに 1 本。特に「同じ 499 型でも L/B が 5.2〜6.3 に
  散る」こと
- `docs/domain-notes.md` — 採用したクラスと代表値、その出どころ

  押船＋バージ）から始め、事案を足すたびに 1 行足す
- **代表値をどの資料から取るか。** 造船所の仕様書 PDF、日本船主協会の新鋭船データ、学会論文。
  `plans/ship-motion-model.md` の「係数の出どころ」と同じ扱いで、クラスごとに出典を持たせる。
  **記憶で埋めない**
- **どのクラスにも合わないときどうするか。** 描画は最近傍で続け、パネルには警告を出す、が素直。
  ただし「最近傍だが遠い」をどこで切るか
- **`draughtMetres` が無いとき。** クラスの満載喫水を使う。ただしそれは満載状態の仮定で、実際の
  事案では空船かもしれない。積付状態は L, B からは出てこない量で、499 型なら満載時の乾舷 2.8 m
  前後に対し空船では 5 m 以上——**見える量が 1.8 倍変わる**。報告書が喫水を書いていないとき
  どちらに倒すか
- **上部構造の作り込み。** 今は箱 1 つ。煙突・マスト・ハウスの段数まで作るかは、ブリッジ視点の
  見え方を見てから決める
