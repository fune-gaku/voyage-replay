# 灯火が水面に敷く筋（issue #39）

## 何を

夜、船の航海灯と標識の灯は**水面に光の筋を敷く**。いまレンダラは灯そのものしか描いていない。

**この画の中で唯一「証拠」になる反射**がこれ。昼の船体の映り込みは誰も何も読み取らない
壊れた光の柱だが、**2 マイル先の紅の舷灯が観測者へ向けて敷く紅い筋は、灯の到達距離を
延ばす署名**で、しかも**方位を持って**届く。

#37 で glitter の機械（ワールド反射ベクトル・Gaussian ローブ・フラグメントごとの幅）が
入ったので、**形は同じで数字が違うだけ**——天体は無限遠、灯は近くて低い。

## 一次情報

- **照射範囲は COLREG 第21条**。マスト灯 225°、舷灯 各112.5°、船尾灯 135°
  （`actors/vessel/lights.ts` が既に持っている）
- **光達距離は第22条**で、カンデラではなく**距離の下限**として書かれている
  （`nominalRangeNauticalMiles`）
- **標識の灯質は IALA E-110**（`core/light-character.ts`）。issue のコメントが指摘するとおり、
  **Q(9) の下に定常の筋を敷くのは、筋を描かないより悪い主張**

## 決めたこと

### 1. 鏡面条件をそのまま点光源へ一般化する

#37 は「反射方向 R が天体の方向と一致するか」を見ている。天体は無限遠なので方向だけでよい。
**灯は有限距離なので、フラグメントごとに `normalize(灯の位置 − 水面の位置)` と比べる**——
それが鏡面条件そのもので、追加の幾何は要らない。筋が「眼の足元と灯の足元を結ぶ線に沿って伸びる」
のは、この条件が水面上でどこで満たされるかの帰結として**勝手に出る**。

ローブの幅も #37 のものをそのまま使う（フラグメントごとに、法線が運んでいない分を足す）。

### 2. 弧は「水面の点」で判定する

灯は自分の弧の中しか照らさない。**弧の内外は水面の点で決まる**（眼の位置ではない）——
灯から見たその水面点の相対方位を、灯を掲げる船の船首方位から測って判定する。
眼が弧の外にいれば鏡面点も弧の外に落ちるので、見えないことは自動的に出る。

`visibleLights` と同じ **180° の罠**がここにある。相対方位は
**「灯を掲げている側の船首を基準にした、照らされる点の方位」**。

### 3. 明るさは主張しない。ただし「灯より先に消える」は強制する

- 灯の強さは第22条が**距離の下限**として書いていて、カンデラは無い。
  水面の反射がどれだけ眼に届くかは海面状態と大気で決まる。**明るさは描けるが主張できない**
- **反射が灯より遠くまで見えたら、それは検出の発明**。ピークは点光源の照度に従って
  `1/r²` で落とし、さらに**第22条の公称距離の内側で 0 になる**ようにクランプする。
  「灯より先に消える」を**コードが守る不等式**として書き、パネルがそう言う

### 4. 灯質は筋にも乗る

`shine()` が既に `showingAt(phases, t)` で灯の色を毎フレーム決めている。
**同じ値で筋も点滅させる**——消費者が 1 つ増えるだけ。
`known: false`（読めない・記載なし）の灯は**筋も描かない**（灯を描かないのと同じ判断）。

### 5. #37 と同じ判断を引き継ぐもの

- **平面図には出さない**（照明・地図・グリッド・glitter と同じ）
- **夜だけ**。昼に航海灯を描かないのと同じ
- **海の記載が無ければ筋も無い**。記載された凪は鏡（天体と同じ扱い）

## 素直な実装だと間違うところ

1. **`normalize(灯 − 水面)` を逆に書く。** 筋は反対側へ伸びるが、静止画では見分けがつかない
2. **弧を眼で判定する。** 舷灯の弧は「誰に見えるか」ではなく「どこを照らすか」。
   眼で判定すると、正横後方から見たときに紅い筋が船首方向の水面に出る
3. **筋が灯より遠くまで残る。** 反射は灯より暗いので、これは**検出の発明**にあたる
4. **点滅を忘れる。** issue のコメントの指摘そのもの
5. **灯ごとに幅を計算し直す。** ローブの幅は海の性質で灯の性質ではない。#37 の
   フラグメントごとの残差を**共有する**（2 か所で計算すると必ずずれる）
6. **灯の数だけ `exp` を回す。** 参照事案で 2 隻 × 5 灯 ＋ 標識。固定長の uniform 配列
   （`SHADER_COMPONENTS` と同じ理由でシェーダの配列長は定数）。**溢れたぶんを黙って落とすと、
   ページは「灯を描いた」と言い画には無い**——落ちた本数をパネルが言う

## 未解決の問い

- **灯の高さは仮定値**（`render/navlights.ts` の `lampPosition` が beam から作っている）。
  筋の長さは眼高と灯高の比で決まるので、**筋の長さは #8 の仮定に乗る**。
  パネルがそう書く必要がある——「方位は計算値、長さは仮定に乗る」
- **標識の灯の高さ**は `heightMetres`（水面から上）なので、そちらは記載値に乗る
