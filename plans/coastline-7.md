# 海岸線（座標グリッドを地図にする）

## 何を

今の平面は水面と可変グリッドだけ（`src/render/scene.ts`）。ここに陸を入れて、事案の位置が
地理として読めるようにする。

**方針を変えた。** 当初はベクタ（GeoJSON）を切り出してシナリオに埋める案だったが、
**ラスタタイルを実行時に取得する**方式を先に入れる。ベクタは後段（下記「残り」）。

## なぜ変えたか

最初の版は「タイルは `build:single` を壊す」としてタイルを落としていた。**この判断は
「焼き込む」場合にしか当たっていない。** 実行時取得と焼き込みは、ライセンス上も容量上も
別物で、そこを分けていなかった。

| | 実行時取得 | 焼き込み |
|---|---|---|
| 地理院タイルの扱い | リアルタイム表示 → 出典明示のみ、申請不要（Q1-12）。動画の背景も不要（Q1-8） | 複製 → 申請フローの判断対象 |
| 容量（この事案、z=15） | 0 | base64 41.6 MB |
| オフラインで開いたとき | 陸が出ない | 出る |

そして**壊れ方が致命的でない**。船・航海灯・トラック・時刻・パネルはすべてファイルの中に
あるので、タイルが来なくても再現はそのまま動き、画面は「この変更の前」に戻るだけ。
`build:single` が守っているのは「viewer が腐らないこと」であって、装飾が全部入っている
ことではない。

工数も桁で違う。ダウンロードも shapefile パーサも簡略化トレランスの判断も要らない。

## 入れたもの

- `src/render/tiles.ts` — Web Mercator のタイル算術（three.js もネットワークも触らない）
- `src/render/basemap.ts` — タイルを **1枚ずつ自分の四隅で** ローカル ENU に置く
- `src/render/overlay.ts` — 右上に時刻、右下に地図の出典を **canvas の中に**描く
- `src/core/time.ts` — 時刻整形（パネルと画中キャプションが食い違わないよう1か所に）
- `src/render/scene.ts` — `MAP_TINT` を1つ。`setDiagramLighting` → `setDiagramView`
  に改名（灯りと一緒に地図も切り替わるため）
- `src/render/player.ts` — 平面図の縮尺（自動／指定）、キャプションを2パス目で描く

**スキーマは変えていない。** 地図の範囲はトラックから決まるので、シナリオに持たせるものが
何も無い。ベクタを入れる段になって初めて `spec/voyage.schema.json` に手が入る。

### 素直な実装だと何が間違うか

1. **1枚の板に一律スケールで貼る。** タイルは Web Mercator、シーンはローカル ENU。
   緯度 33.9 の縮尺係数は 1.2048 で、**南北 22 km で 40 m ずれる**。海岸線が船の全長より
   大きく動く。タイルごとに四隅を `toLocalPosition` に通せば、残るのはタイル内部の歪みだけで
   z=13 で 7.3 m、z=14 で 3.6 m、z=15 で 1.8 m——出典データの精度（0.1 秒 ≒ 3 m）の下。
   `test/basemap.spec.ts` が「行と行が隙間なく接する」ことで固定している
2. **タイルの行番号は北から数える。** 逆に読むと、箱が縦に長いときだけ地図が上下逆になる
3. **画像が来る前にメッシュを出す。** 水の上に tint 色の平板が出て、浅所か何かに見える。
   届くまで隠す
4. **ズームを固定する。実際に踏んだ。** 平面図は数十 km から数百 m まで、**100 倍を超える
   ズーム域**を動く。1段では賄えない。最初の版は固定範囲を1回取ってきて両端でフェードさせたが、
   結果は「中くらいのスケールでだけ地図が出て、他では出ない」で、これは地図として使えない。
   **タイルクライアントと同じように、フレームからズームを選んで取り直す。**
   取得範囲はフレームの 1.4 倍に広げてあるので、その中でのパンは取り直さない。
   ズーム判定を入れ忘れると同じ罠に戻る——**寄る方向では画面は取得範囲から出ない**ので、
   「範囲内か」だけ見ていると最初に読んだ段のまま張り付く
5. **新しい段を入れる前に古い段を消す。** 新しいタイルは画像が届くまで不可視なので、
   ズームが 2 の冪をまたぐたびに地図が一瞬消える。**次の段が1枚届いてから捨てる**
6. **夜のパレットに合わせて地図を暗く乗算する。実際に踏んだ。** 淡色地図は陸と海の明度差が
   1割程度しかないので、暗く落とすとその差ごと持っていかれて、ただの黒い染みになる。
   **夜に見えるほど暗い＝読めないほど暗い。** `setDiagramView` が照明について既に出している
   結論と同じ——平面図は図面であって夜ではない。乗算色は light condition で変えず 1つだけ
   （`MAP_TINT = 0xe6ecf0`）。船橋視点は夜のまま。
   捨てた手がかり（暗い平面図＝夜の事案）は、**右上の時計**で読み取れる形に戻してある
7. **出典を DOM に置く。** 録画は `canvas.captureStream()` なので、canvas の外は動画に映らない。
   出典は画の中に描く必要がある
8. **タイルが来なくても出典を出す。** 日本の外では 404 になり地図は出ない。出ていない地図の
   出典を書くのは虚偽なので、最初の1枚が届いたときだけ出す
9. **WebGL は CORS の無い画像をテクスチャにできない。** Leaflet（DOM の `<img>`）には無い制約で、
   同じ URL があちらで動いてこちらで落ちる。`setCrossOrigin("anonymous")` を明示してある

## 残り（ベクタ海岸線）

タイルが解かない問題が2つある。**オフラインで陸が出ない**（船上・法廷・ネットの無い会議室）、
**開くたびに「どの海域をいつ見たか」がタイルサーバに出る**（守秘の要る顧客案件）。
どちらもベクタをシナリオに埋めれば消える。

- シナリオに `coastline`（GeoJSON の Polygon / MultiPolygon + 出典 + ライセンス）を持たせる
- `three` 同梱の earcut（`ShapeUtils.triangulateShape`）で三角形化。新規依存ゼロ
- **あればベクタを優先し、無ければタイル**。絵が2種類あること自体は避けられないので、
  どちらを見ているかがパネルから分かる必要がある
- データ源は **国土数値情報（国土交通省）の行政区域データ**。出典明示で再配布可、1:25,000 相当。
  簡略化 20 m・座標5桁で 40〜100 kB の見込み（実測して決める）

比較して落としたもの:

- **Natural Earth** — パブリックドメインで一番緩いが 1:1000 万想定。3〜20 km の画面には粗すぎる。
  広域の位置図（インセット）としてなら使える
- **OpenStreetMap** — 精度は十分で世界中を覆う。動画は ODbL の Produced Work なので帰属表示だけで
  済む（share-alike は Derivative Database だけ、4.5(b)）。ただし GeoJSON を切り出してこのレポに
  置くと、そのファイル自体が Derivative Database で ODbL になり、MIT のコードと二本立てになる
- **海図**（海上保安庁 / 日本水路協会）— 有償・許諾必要。使わない

## 未解決

- ~~取り直しの頻度~~ **入れた。** 視界が動いている間は取りに行かず、**止まって 250 ms** して
  から取る（`SETTLE_MS`）。連続ズームが通過する段は取りに行かないので、オープニングショットの
  400〜500 枚が 2 段ぶんに落ちる。待っている間は既に載っている段が拡大表示されるだけで、
  これは slippy map が普通にやっていること。ただし**まだ何も載っていないときは待たない**
  （保持すべき絵が無い）。テストは fake timer で `settle()` を挟む形
- **淡色より白地図（`xyz/blank`）のほうが良いかもしれない。** 道路も地名も無く海陸だけ。
  ただし z14 までしか無い（はず——未確認）。いまは z5〜18 の淡色を使っている
- **潮位。** 地形図の海岸線は満潮時の水陸境界。座礁や浅所が絡む事案では等深線が要る。
  別データ、ライセンスも別途確認（GEBCO、海上保安庁）
- **日本の外の事案。** 地理院タイルは日本で止まる。外航事案では地図が出ない。OSM ベースの
  タイル（CARTO Positron 等）を第2層に敷くか、ベクタで賄うか
- **海岸線より航路と灯台のほうが効くのではないか。** 「なぜその針路だったか」を読ませるのは
  航路筋・分離通航方式・灯台の位置。別 issue に切るかどうか
- **縮尺の読み。** 陸が入るとグリッドだけでは縮尺が読みにくくなる。ホイールが連続ズームに
  なったので、いま画面が何 km なのかはセレクトの `manual` 項目にしか出ていない。
  録画にも残る形にするならスケールバーを画中キャプションに足すのが筋（時計と同じ仕組み）
- **引きすぎたときの投影歪み。** 全部が原点固定の1枚の平面に投影されている（`core/geodesy.ts`）。
  数 km ではセンチ単位だが、100 km で東西 1.1%、500 km で 5.9%、1000 km で 13.3% 伸びる。
  縮尺セレクトは 1000 km まで開くようにしたので、広い側は「どの海か」を見るためのもので
  距離を測るものではない。いまは title 属性に書いてあるだけで、画面には出していない。
  出すなら時計と同じ画中キャプションに置くのが筋
