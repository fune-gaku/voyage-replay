# 風を持てるようにする（issue #43）

## 何を

`environment.wind` を足し、いま塞いであるだけの仮定を消す。`core/seaway.ts` が風を使い、
パネルがどこから来た値かを書く。

## 素直な実装だと間違うところ

### 1. 風が決めるのは風浪であって「海」ではない

遠方の低気圧から来るうねりは別方向から走る。それが普通で、実海面が混沌として見える理由。

**優先順位は3段**にする。`waves.fromDegreesTrue`（記載）＞ 風向から導出 ＞ 名前の付いた仮定。
パネルはどの段だったかを書く。風を足しても仮定が消えるのではなく、**段が1つ増えて仮定が
後退する**だけ。そう書く。

### 2. 完全発達には吹送距離と継続時間の両方が要る

`Hs = 0.21 U²/g` は完全発達の関係で、風が上がっている最中の海はそれより小さい。
つまり**風は波高の上限であって波高ではない**。逆向きの誤りは無い——記載の海が風の支える
上限より大きければ、うねりか転記ミス。

**だから突き合わせは非対称。** `statedLightAgrees` が「比較できる軸でだけ比較する」のと同じで、
「海 ≫ 風の上限」だけを報告し、「海 ≪ 風の上限」は普通のこととして黙る。

### 3. ビューフォートは階級であって数値ではない（そして端が2つとも普通でない）

BF5 は 17〜21 kn。海面状態を中央値で潰さなかったのと同じ理由で潰さない。

**そこで役割を分ける。** 風速が記載されていれば周期の導出に使う。**風力階級しか無ければ
範囲として運び、突き合わせと風向にだけ使う**——単一の周期を出すために中央値を発明しない。
風力階級の主な価値は突き合わせと風向のほうにあるので、これで失うものは小さい。

### 4. 周期の導出は「順方向」になるが、バイアスの向きは変わらない

いまの `assumedPeakPeriodSeconds` は Hs → U → Tp と PM を逆に回している。風速があれば
U → Tp で済む。ただし**どちらも完全発達を仮定するので、内海で長く出るバイアスはそのまま**。
消えるのは往復であって偏りではない。そう書く。

## どのファイル

- `spec/voyage.schema.json`, `src/core/types.ts` — `environment.wind`（`derivation` 必須）
- `src/core/seaway.ts` — ビューフォート換算（範囲）、風速からの周期、風向の優先順位、
  完全発達の上限と突き合わせ
- `src/core/conditions.ts` — `Conditions` に風を載せる
- `src/ui/panels.ts` — 風の行、波向がどの段から来たか、突き合わせの結果
- テスト — ビューフォートは公表値に、PM は公表の係数に、優先順位と非対称な突き合わせを固定

## この変更に入れないもの

- **吹送距離の計算。** 風向と海岸線から求まり、地形タイルは既にある。既知バイアスを注記から
  計算に変える話で、それ自体が独立している
- **風浪＋うねりの2成分スペクトル。** 実海面はそうだが、`seaway.ts` の全体を触る
- **リーウェイ（風圧流）。** 船の話であって海の話ではない

## 追記: 16反復のレビューで分かったこと

指摘は Codex 15件・私 21件。**そのうち圧倒的多数が同じ2つの型**だった。

### 1. 階級の端を「数字」と読む（8件）

このレポは階級だらけで、そのうち3つは端が数字でない。

| | 端 | 何になっていたか |
|---|---|---|
| 海面状態 9 | 上端が**床** | 14 を上限として読み、有限の風から周期を導出 |
| ビューフォート 12 | 上端が**床** | `[64, 64]` を同値と見て「開いている」を落とす |
| ビューフォート 0 | 上端が**排他** | 1 kn を calm と判定し、不一致注記を消す |

**`forceClass` / `seaStateClass` に集約した。それでも足りなかった**——値を受け取る側が閉区間として読み直せば同じことが起きる（正しく「1 kn 未満」と持ちながら、注記だけが「階級の上端の 1 kn」と書いた）。**端を持つ値は、計算する層だけでなく印刷する層でも端を尊重する。**

### 2. 「値が無い」の扱いが浅すぎるか行き過ぎる（7件）

無風から 0.5 秒の周期が出る問題を、**3層かけて**やっと止めた:

1. 関係式を 0 を返すように直した → `seawayOf` が 0.5 にクランプし直した
2. 判定を穏やかな側から荒い側へ移した → 開区間の階級で通り抜けた
3. `periodFrom: "none"` を作った → **今度は記載の周期・方向まで飲み込んだ**

減衰したうねり（波高 0・周期 8 s・波向 270）は実在する。**導出の規則が記載値を隠してはいけない。**

### 3. 却下の理由は網羅的な列挙で持つ

真偽値2つで「弱すぎた」「風力だけ」を表そうとしたら、**海面状態 9 に 150 kn を「弱すぎた」と偽った**（16.6 m 起こせる）。理由は4つあった。**間違った理由を名指すのは、理由を言わないより悪い**——読者に正しかった数字を直させる。

### 4. 散文は分岐を1つ選ばず、全部レンダリングして読む

8通り読んで6件出た。1つ読んで直すと、直した分岐だけが正しくなる。テストも、直した文に現れる形だけを否定すると隣の文が素通りする（`"s at the rough end"` を否定して `"at the rough end the highest tenth"` が残った）。

### 5. 有界なフィールドを足したら3点セットを当て直す

スキーマの境界・コードのクランプ・両者を結ぶテスト。波高と周期で2反復かけて学んだのに、**風速に足したとき適用しなかった**。
