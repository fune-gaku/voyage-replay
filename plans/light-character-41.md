# 灯質を1つの文法として持つ（issue #41）

## 何を

灯質（rhythmic character）は標識の装飾ではなく、**標識そのものの識別子**。IALA の方位標識は
灯質以外では区別がつかない。

| | 灯質 |
|---|---|
| 北方位 | VQ / Q |
| 東方位 | VQ(3) 5s / Q(3) 10s |
| 南方位 | VQ(6)+LFl 10s / Q(6)+LFl 15s |
| 西方位 | VQ(9) 10s / Q(9) 15s |

（IALA Recommendation **E-110** Ed.4.0 (Dec 2016) Table 3。以下すべて同文書。）

**マークごとに点滅表を持たない。** 閉じた小さい文法（級・群数・複合群・色・周期）から
**1か所で生成する**——`core/celestial.ts` が時刻と場所から高度を出すのと同じ形。
データに文法を持たせると、シナリオごとに書き直され、それぞれが別々に間違う。

## 一次情報（E-110 Table 2 / Table 3）

級と制約。**数値はすべてこの表から取り、推測しない。**

| 級 | 略号 | 制約（E-110 "IALA Specification"） |
|---|---|---|
| 定光 | F | 単独では使わない（MBS では **禁止**） |
| 明暗 | Oc | 明 ≥ 3×暗、周期 ≥ 2 s |
| 群明暗 | Oc(#) | 群内の明 ≥ 暗、群間の明 ≥ 3×群内の明、群数 ≤ 4（例外的に5） |
| 等明暗 | Iso | 明 = 暗、周期 ≥ 2 s（できれば ≥ 4 s） |
| 単閃 | Fl | 暗 ≥ 3×閃、周期 ≥ 2 s、閃光率 **< 50/分** |
| 長閃 | LFl | 閃 ≥ **2 s**、暗 ≥ 3×閃 |
| 群閃 | Fl(#) | 群内の暗 ≥ 閃、群間の暗 ≥ 3×群内の暗、群数 ≤ 5（例外的に6） |
| 複合群閃 | Fl(#+#) | (2+1) が原則、(3+1) は例外 |
| 急閃 | Q / Q(#) | **50〜79/分**（IALA 指定は 60/分）、群数は 3 または 9、南方位のみ 6+LFl |
| 超急閃 | VQ / VQ(#) | **80〜159/分**（指定 120/分）、同上 |
| 極急閃 | UQ | **160〜300/分**（指定 240/分） |
| モールス | Mo(#) | 短点 ≈ 0.5 s、長点 ≥ 3×短点、1文字が原則 |
| 互光 | Al | 色が交互 |

最大周期（Table 1）: Iso 12 s / 単閃・単明暗・群超急閃 15 s / 長閃・2群 20 s / 3群以上・
複合群・モールス 30 s。

## 素直な実装だと間違うところ

### 1. 略号は on/off の長さを決めない——ここが一番の罠

`Fl 4s` は「4秒に1閃」しか言っていない。**閃光の長さは言っていない。** E-110 が与えるのは
**制約と例**であって関数ではない（Fl の例は `d = 3 s, l = 1 s, p = 4 s`、しかし制約は `d ≥ 3l`
だけなので `l = 0.5 s` も適合する）。実際の分割はその灯の灯台表にある。

したがって**生成した列は `inferred`** であって `measured` ではない。この工具が他のすべての
数字に課している規律と同じで、描くところにも表示するところにも出す。ファイルが実測の
duration を書いていればそれを使い、出所をそう言う。

### 2. 閃光率の帯を周期の上限から読まない

E-110 の急閃の欄には `1 s ≤ p ≤ 1.2 s` とある（60〜50/分に対応）。超急閃の欄の対応する数字は
PDF から `0.5 s ≤ p ≤ 1.6 s` と読めるが、**80/分は 0.75 s** であって 1.6 s ではない。
**帯（50〜79 / 80〜159 / 160〜300 回毎分）のほうが2箇所に書かれていて曖昧さがない**ので、
周期の範囲はそこから割り出す。PDF のレイアウト復元を数字の出典にしない。

### 3. 「灯火なし」と「記載なし」を同じ空欄にしない

浮標には灯浮標と（灯りのない）浮標があり、立標と灯標も同じ関係。**`light` が無いファイルは
「灯りが無かった」ではなく「誰も書かなかった」**。#40 の振れ回り円で3値にしたのと同じ判断で、
描画は何も光らせず、パネルは「記載が無い」と書く（「無灯」とは書かない）。

### 4. 昼に光らせない・平面図で点滅させない

灯質は夜の主張。`core/conditions.ts` の判定を使い、平面図は図面なので点滅しない
（`setDiagramView` が照明・地図について既に出している結論と同じ）。

### 5. 解析できない灯質を「それらしい既定」に落とさない

`Fl(2) W 10s` を読めなかったときに単閃へ落とすと、**孤立障害標が特別標識に化ける**。
読めなければ点滅させず、パネルがそう書く。

## どのファイル

- 新規 `src/core/light-character.ts` — 文法。`parseCharacter()` / `phasesOf()` /
  `isShowing(character, secondsFromStart)` / `describe()`。**three.js も船も知らない**
- `spec/voyage.schema.json`, `src/core/types.ts` — `marks[].light`
  （`character` 文字列、灯色、実測 duration の任意指定、`source`）
- `src/render/mark.ts` — マストの上に灯を1つ吊る（いまは何も吊っていない）
- `src/render/player.ts` — 各フレームで `isShowing` を引いて可視を切り替える
- `src/ui/panels.ts` — 灯質、その意味（E-110 Table 3 が割り当てているもの）、
  分割が記載か推定か
- `docs/domain-notes.md` — E-110 の表と、この4つの罠

## この変更に入れないもの

- **意味から灯質を生成する**（#42）。ここは灯質を*運ぶ*だけで、方位標識の意味からの導出は
  #42 が同じ真実の源を持つべきと言っている
- **水面への映り込み**（#39）。点滅する灯の水路は #37 の反射計算の上に乗る
- **目撃証言との突き合わせ**（「白光、約4秒に1閃」）。`statedLightAgrees` と同じ形にできるが、
  証言を運ぶフィールドがまだ無い
- **船の灯火への適用**。ブロックは標識を前提にしない作りにするが、船側の配線は別
