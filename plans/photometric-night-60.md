# 夜を測光的にして、トーンマッピングを入れる（issue #60）

## 何を

灯は測光的になった（第22条 → 光度 → 水面の lx）が、**海と空は「そう見えるように選んだ色」のまま**。
`NIGHT.water = 0x0a121d` は星明かりの海の **50 倍ほど明るい**ので、正しく計算された灯の
レーン（水面の 1/10〜1/5）はそこに埋もれる。

そして輝度の幅が大きすぎて、**線形では 2 つ以上を同時に出せない**:

| | 輝度 |
|---|---:|
| 月の無い晴れた夜空 | 約 2×10⁻⁴ cd/m² |
| それを映す海面 | 0.4〜2×10⁻⁴ |
| マスト灯のレーン（250 m） | 約 5×10⁻⁴ |
| 満月の光の道 | 約 0.3 |
| 晴れた昼の空 | 約 5000 |

夜の海と満月の道で 1500 倍、夜と昼で 10⁷ 倍。**白飛びするか、計算したものが見えなくなるか**の
どちらかにしかならない——この 1 時間で両方起きた。

## 決めたこと

### 1. 光を実単位で持つ

three の非レガシー照明（`useLegacyLights = false`、r155 以降は既定）は
`DirectionalLight.intensity` を **lx** で取り、標準マテリアルの色を**アルベド**として扱う。

- **夜**: 環境光＝星明かり 0.002 lx、指向性＝月 0.018 lx（参照事案の 41% の月。位相則で計算）
- **昼**: 環境光＝空 2×10⁴ lx 程度、指向性＝太陽 6×10⁴ lx 程度

### 2. トーンマッピングと、条件ごとの露出

フィルミックな曲線（ACES）で上を丸める。**露出は条件ごとに 1 つだけ宣言**——
`ambient` が既にそうであるのと同じ形で、宣言はむしろ 1 つに減る。

### 3. パレットは「アルベドと放射輝度」になる

**色相は選んだままだが、大きさは選ばなくなる。** 船体・陸・地図の乗算色・標識・航跡線・
グリッドは全部アルベドとして読み直す。

### 4. 夜の暗さは「別の道で同じ暗さ」に出す

このレポは**夜の暗さを証拠として扱う**（`setDiagramView` の判断、`MAP_TINT` の判断）。
測光的にしたら夜が明るくなった、では退行。**露出を決めたあと、夜が夜のままであることを確かめる**。

## 素直な実装だと間違うところ

1. **ACES は暗部を持ち上げる。** 何もしないと夜が灰色になる。露出で相殺し、実測で確かめる
2. **`useLegacyLights` の切り替えは全マテリアルの明るさを変える。** 段階的に測りながらやる
3. **平面図は写真ではない。** 海図の照明・地図の乗算色はトーンマッピングの影響を受けてよいが、
   「読める」ことが要件。`setDiagramView` の既存の判断を壊さない
4. **灯のスプライト（`Points`）は測光的ではない。** 灯そのものは固定サイズの点で、
   露出を変えると浮く。灯の見かけの明るさも条件に合わせるか、合わせないなら宣言する
5. **パネルの文が古くなる。** 「明るさは選んだ値」は**部分的に**しか正しくなくなる
