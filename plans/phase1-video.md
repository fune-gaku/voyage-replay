# Phase 1 — 仕様どおりの `.voyage.json` から動画を作れるところまで

## ゴール

`examples/suo-nada-2025-11-27.voyage.json` を読み込み、3D で再生し、**動画ファイルとして
書き出せる**。そこまでで Phase 1 を閉じる。

抽出（PDF → JSON）と配布（npm publish / CLI）は Phase 1 に含めない。入力は仕様どおりの
JSON が既にある前提。

## 入れるもの

1. **シーン** — 平らな海面。夜間なので暗い。空は単色でよい
2. **船体** — `vessel.loaMetres` / `beamMetres` から生成。ローポリ。3D モデルは探しに行かない
   （権利が面倒で、そもそも寸法が入力なので生成のほうが正しい）
3. **航海灯** — `src/actors/vessel/lights.ts` の照射範囲をそのまま描く。**ここが主役。**
   船体の作り込みより優先する
4. **カメラ3種** — 俯瞰（正射影・北上固定）／各船の船橋。船橋位置は
   `referencePointOffsets` から推定
5. **タイムライン** — スクラブ、可変速、時計常時表示
6. **出所の描き分け** — `derivation` が `measured` 以外の航跡区間は破線・半透明
7. **録画** — `canvas.captureStream()` + `MediaRecorder` で webm を書き出す

## 入れないもの

運動モデル、波・航跡波・水面シェーダ、天候、音、レーダ／ARPA 画面、3隻以上、
ヘッドレス書き出し、CLI、抽出。

## 運動モデルを入れない理由（実測）

直線補間は本来正しくない（船は舵の効き遅れを持ち、旋回を惰性で引きずり、船首は進行方向から
偏角ぶんずれる）。ただし**この参照事案では破綻が見えない**。

| | A船 | B船 |
|---|---|---|
| 標本間隔 | 最小 6s / 中央 60s / 最大 1180s | 最小 9s / 中央 50s / 最大 609s |
| 針路が 10° 超変わる区間 | 3/28、その間隔は最大 **13s** | 4/29、最大 **40s** |

20 分の穴は針路が一定の直進区間で、回頭している場面は 6〜13 秒刻みで打たれている。
調査官が臨界期だけ高解像度で AIS を抜いているため。さらに A 船の 2.3〜2.7°/s という
急な回頭は 18:13:24 以降＝**衝突で船体が振られた瞬間**で、操船ではない。実際の避航動作は
18:11〜18:13 の 26°/134s（約 0.2°/s）。

運動モデルが要るのは Tier B/C の疎な航跡のほう。`plans/ship-motion-model.md` に残す。

## 録画方式

`MediaRecorder` で canvas を直接録る。画面収録に対して 3 つ勝る。

- ウィンドウのサイズや他のアプリに影響されない
- 可変速再生でもコマ落ちしない
- 録り直しがワンクリック

弱点は webm 固定であること（YouTube は webm を受け付けるので実用上は問題ない）。
mp4 が要るなら ffmpeg で変換するか、後のフェーズでヘッドレス書き出しを作る。

## 触るファイル

```
src/render/scene.ts     シーン・海面・環境光
src/render/hull.ts      寸法から船体ジオメトリを生成
src/render/navlights.ts 航海灯の描画（照射範囲つき）
src/render/cameras.ts   俯瞰・船橋カメラ
src/render/player.ts    再生ループとタイムライン
src/render/record.ts    MediaRecorder
src/main.ts             組み立て。今のテキスト表示はパネルとして残す
```

`src/core/` には three.js を持ち込まない。`core/` は「時系列と幾何」だけを知っていればよく、
描画は `render/` と `actors/vessel/` が持つ。

## 未解決

- **船橋の高さ。** `referencePointOffsets` はアンテナの水平位置しか教えてくれない。
  脚注は「船橋上方に設置された」と書いているので水平位置はほぼ同じだが、高さは船種と
  全長から推定するしかない。推定値をどこかに明示する
- **航海灯の見え方。** 実際の灯火は距離とともに暗くなる。Rule 22 の公称光達距離を
  そのまま減衰に使うか、見やすさを優先するか。夜間のシーンは「暗すぎて何も見えない」に
  なりやすい
- **時間圧縮の既定値。** この事案は 17:20〜18:16 の約 56 分。等速では見られない。
  どこを何倍にするかをシナリオに書けるようにするか、UI で決めるか
