# plans/

1 変更につき 1 メモ。実装の前に書く。ファイル名は `<slug>-<issue番号>.md`——
**issue が入口で、ここは設計判断の置き場**。小さい修正に plan は要らず、issue だけでよい。

書くこと:

- **何を** 変えるか
- **なぜ** それが必要か。特に「素直な実装だと何が間違うか」
- **どのファイル** を触るか
- **未解決の問い**

書かなくていいこと: 実装そのものの逐次手順、コードの貼り付け。

実装 PR に `Closes #N` を書き、merge したら `plans/done/` へ移す。移すときに、実際にやったことが
書いてあることと違っていたらそこを直してから移す——次に同じところを触る人が読むのは、
計画ではなく記録のほう。

移し忘れは実際に起きる。`phase1-video.md` は実装が入ったあともしばらくここに残っていて、
その間 README は「レンダラは未実装」と書き続けていた。
